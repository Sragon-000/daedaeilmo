# 대대일모 프로젝트 개선 방향

> 이 문서는 학생 우선 방향의 기준안이다. 기관을 고객으로 둘 경우의 변경안은 [기관 고객 전환 계획](./institution-first-roadmap-2026-10-13.md)에서 검토한다.

작성 기준: 2026-09-27. 이 문서는 팀 문서의 **검증된 관찰**, **아직 확인하지 않은 가설**, **현재 코드의 구현 상태**를 구분한 실행 계획이다. 문서 속 수업 과제나 AI 프롬프트는 실행 지시가 아니라 기획 근거로만 다뤘다.

개발 반영(2026-09-27): 행사 D1 보관·원문 변경 시 검수 해제, Mac 관리자 검수·숨김·정정, 일반공지 1~3페이지의 최근 후보 수집, 검색·분야·저장 목록, 원문 열기 기록을 구현했다. 아래 현황 비교표는 **개발 착수 전 기준**이며, 20건 수동 품질 점검·10명 사용자 실험·상시 수집은 아직 완료하지 않았다.

## 결정할 제품 방향

첫 검증 범위는 **배재대 학생이 여러 경로를 다시 찾지 않고, 믿을 수 있는 비교과 활동 후보를 확인해 학교 원문까지 도달하는 모바일 웹 서비스**로 좁힌다. 공강 비교는 유용한 보조 기능이지만, 그것만으로 탐색 중단이나 참여 증가가 해결된다고 주장하지 않는다. 4주차 워크북은 두 학생 인터뷰에서 한 명이 포스터를 편하게 봤고 일정 충돌 때문에 신청하지 못했으며, 다른 한 명은 여러 경로를 거쳤지만 탐색 시간이 1분이었다고 기록한다. 따라서 ‘정보 탐색이 늘 어렵다’는 기존 가설보다, 팀이 선택한 **캔버스 B의 실제 확인 행동**을 먼저 검증한다.

초기 사용자는 배재대 학생으로 유지한다. 계명대 연동, 기관 유료 상품, 독립 모바일 앱은 첫 실험의 성공 조건이 아니다. 현재 코드도 배재대 로그인과 배재대 행사 수집만 제공한다.

## 우선순위

### P0  실제 행사 목록의 신뢰성을 먼저 확보

1. 배재대 공식 공개 채널을 목록화해 어떤 게시판이 비교과 활동을 다루는지 확인한다. 첫 페이지·제목 키워드에만 의존하지 않도록 수집 범위와 누락 사례를 기록한다. 허가되지 않은 로그인 자료 수집은 범위에 넣지 않는다.
2. 행사별로 `원문 URL`, 게시·수정·수집 시각, 행사 일시, 신청 마감, 장소, 대상, 출처, 추출 근거, `확인됨/확인 필요/종료` 상태를 저장한다. 같은 행사의 재게시·수정을 식별한다.
3. 관리자 화면에서 일정·자격·마감의 **수동 확인·정정**과 오래된 정보 숨김을 지원한다. 자동 추출과 OCR은 초안으로 취급하고, 불명확하거나 본문과 충돌하면 시간표 ‘여유’ 판정을 하지 않는다.
4. 실제 공지 20건을 표본 점검해 누락, 중복, 지난 행사, 잘못된 일시·대상 표시를 기록한다. 잘못된 ‘참여 가능’ 표시가 있으면 자동 판정 범위를 줄인다.

**완료 기준:** 표본의 각 카드에서 원문과 최종 확인 시각을 찾을 수 있고, 종료·모호한 일정을 명확히 구분하며, 관리자가 오류를 수정할 수 있다. ‘행사 수가 몇 건인가’보다 사용자가 실제로 고려할 유효 후보가 있는지를 함께 보고한다.

### P1  한곳에서 확인하고 원문으로 가는 경로를 완성

1. 행사 카드의 포스터는 유지하되 제목, 핵심 일시, 장소, 대상, 마감, 원문 버튼을 먼저 읽을 수 있게 한다. 정보가 없으면 빈칸을 추측으로 채우지 않고 ‘원문 확인 필요’로 표시한다.
2. 검색·관심 분야 필터와 **저장 목록**을 추가한다. 저장은 서버에 유지하고, 원문 클릭과 구분한다. 마감 알림은 정확한 마감 정보와 재방문 수요가 확인된 뒤 붙인다.
3. 첫 로그인에서 시간표 입력을 안내하되 ‘나중에 입력’을 허용하는 방안을 실험한다. 시간표를 넣지 않아도 실제 공지를 보고 원문을 열 수 있어야 한다. 입력한 경우에만 ‘시간표상 여유’라고 표현하고, 자격·정원·근로·개인 일정은 판정 대상이 아님을 보여 준다.
4. 이벤트별 `목록 노출 → 상세/원문 클릭 → 저장 → 다시 확인`을 개인정보를 최소화해 계측한다. 클릭은 신청이나 참여로 집계하지 않는다.

**완료 기준:** 테스트 사용자가 실제 활동을 찾아 학교 원문을 열고, 필요하면 저장했다가 다시 찾을 수 있다. 시간표가 없어도 핵심 경로가 막히지 않는다.

### P2  10명·2주 실험으로 문제와 솔루션을 판정

1. 4주차 문서에서 미완료인 10명 명단과 섭외 상태를 먼저 채운다. 최근 직접 탐색자·미탐색자, 신청자·미신청자를 나눠 모집하고, 첫 2명은 전체 학생의 비율로 일반화하지 않는다.
2. 과거의 마지막 탐색 경험을 확인한 뒤, 같은 난이도의 실제 활동 찾기 과제를 기존 방식과 대대일모에서 비교한다. 찾지 못한 사례와 해당하는 행사가 없었던 사례도 분모에서 빼지 않는다.
3. **기획서 v2의 잠정 판정선**인 탐색 시간 중앙값 50% 감소와 10명 중 6명 이상 서로 다른 날 2회 사용을 확인한다. 4주차 선택안 B에 맞춰 원문 도달·저장률, 2주차 자발적 사용, 입력 이탈, 유효 행사 공급 부족을 함께 본다. 이 수치는 시장의 검증된 기준이 아니라 팀의 실험 기준이다.
4. 검색·대조 때문에 포기한 경험, 단순 일정 충돌, 관심 부족, 자격 미달을 분리해 기록한다. 결과가 기준에 못 미치면 가장 큰 원인 한 축만 바꿔 재실험한다.

**완료 기준:** 수치와 실패 사례를 함께 기록한 실험 결과가 있어야 다음 확장 결정을 내릴 수 있다. 앱 사용 의향 설문만으로 성공을 선언하지 않는다.

### P3  학생 가치가 확인된 뒤의 확장

- **기관 연계:** 비교과 담당자에게 목표·신청·실참여·수료, 정보 갱신 업무, 실제 예산·승인 경로를 묻는다. 기관용 등록 화면이나 유료 상품은 담당자 협조와 수요가 확인된 뒤 설계한다.
- **공간 리뷰:** 사용자가 요청했던 기능은 보관한다. 공식 공간 목록과 운영 정책을 확인한 뒤 실제 공간만 리뷰할 수 있게 하고, 작성자 표시명 선택·신고·삭제 절차를 완성한다. 현재 화면에는 실제 공간 목록이 없고 리뷰 API에는 과거 예시 공간 ID가 남아 있다.
- **다른 대학:** 배재대의 탐색·콘텐츠 품질과 운영 절차가 검증된 다음, 학교별 공개 정보 구조와 인증 승인·테스트 계정을 각각 확보한다. 학번·비밀번호 형태가 비슷하다는 이유만으로 같은 연동이 된다고 가정하지 않는다.
- **운영 안정화:** 파일럿 확장 전에 고정 HTTPS 주소, Mac 재시작 후 복구, 학교 로그인 실패 대응, 공유 저장소 기반 시도 제한과 세션 취소, 식별 키 분리, 사진 포함 백업·복구 점검을 마련한다. iOS·Android 배포 여부는 모바일 웹 사용성 검증 후 결정한다.
