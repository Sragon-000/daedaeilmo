# 대대일모 모바일 UI 프로토타입

배재대학교와 계명대학교의 공강 추천·시간표·공간 리뷰를 체험하는 모바일 화면입니다. 모든 화면은 모바일 폭(최대 430px), 하단 내비게이션, 전체 화면 상세와 리뷰로 구성됩니다. 웹으로 실행하는 프로토타입이며 Android APK나 iOS 앱 빌드는 아닙니다.

## 실행

- npm install
- npm run dev
- npm run build
- node --experimental-strip-types scripts/test-notices.mjs

## 구현 기능

- 두 학교 선택과 명시적 데모 입장
- 사용자가 직접 입력하는 주간 시간표, 수업 추가·삭제와 충돌 검사
- 수업 사이 빈 시간과 이동 여유 10분에 따른 예시 활동 추천
- 예시 활동 검색·분류·저장, 행사 시간과 마감일 구분
- 학교별 예시 공간 리뷰, 별점, 작성·수정·삭제와 차단 체험
- 마감 알림 설정 체험
- 실제 공개 공지 조회와 원문 링크: 배재대 일반공지와 계명대 학사공지

## 실제 공지 연결

GET /api/notices?school=pcu 또는 school=kmu

서버가 미리 지정된 학교 HTTPS 주소에서만 공지 제목·원문 링크를 읽습니다. 임의 URL을 받을 수 없으며, 외부 도메인 링크는 파싱에서 제외합니다. 실시간 조회 성공 시 5분간 캐시합니다. 실패 시 data/school-notices.json의 실제 수집 자료와 확인 시각, 연결 지연 안내를 함께 돌려줍니다. 예시 활동을 실제 공지로 대체하지 않습니다.

확인 결과: 로컬 API에서 배재대는 live 12건, 계명대는 TLS 연결 문제로 snapshot 15건을 반환했습니다. 계명대 공개 페이지 자체는 시스템 인증서를 사용하는 curl로 읽었고, 수집 결과를 스냅샷으로 기록했습니다. 인증서 검증을 끄지 않았습니다. 게시 시점 이후의 실시간 연결 상태는 달라질 수 있습니다.

## 배재대 계정 인증

이용 조건은 재학 상태와 관계없이 배재대 포털 로그인 성공입니다. 계명대 연결은 사용자 요청으로 보류했습니다. 시간표는 학교에서 가져오지 않고 직접 입력합니다.

배재대 공식 포털의 RSA 공개키 발급 → 암호화 로그인 → 새 세션으로 보호된 `/main.do` 조회를 서버에서 수행합니다. 각 로그인 시도는 별도 메모리 쿠키 저장소를 사용합니다. 학교 비밀번호와 쿠키는 저장하거나 로그에 출력하지 않습니다. HTTPS의 portal.pcu.ac.kr와 sso.pcu.ac.kr만 허용하고 쿠키를 도메인별로 구분합니다. SSO 서버 → 포털 인증 콜백 → 보호된 메인 화면의 순서를 확인합니다. 포털 구조가 달라져 성공을 확인할 수 없으면 인증 세션을 발급하지 않습니다.

성공하면 학번 원문을 포함하지 않는 서명된 앱 쿠키를 발급합니다. 유효기간은 30분이며 HttpOnly, SameSite=Strict, HTTPS에서 Secure 속성을 사용합니다. GET /api/school-auth로 확인하고 DELETE로 현재 브라우저에서 로그아웃합니다. 로그아웃은 다른 기기에 복사된 쿠키를 서버에서 취소하는 기능은 아닙니다. 학교 세션이 앱 쿠키 발급 이후 종료되어도 앱 쿠키는 만료까지 유지됩니다.

로컬 실행에는 무작위 32바이트 이상의 SCHOOL_SESSION_SECRET을 `.dev.vars`에 설정합니다. 이 파일은 Git에서 제외합니다. 배포 시에는 같은 이름의 별도 비밀 값을 Sites 런타임에 설정해야 합니다. 비밀 값이 없으면 인증은 닫힌 상태로 작동합니다.

현재는 비공개 프로토타입용입니다. 계정별 시도 제한은 Worker 인스턴스의 메모리에 있어 공개 운영 전에는 공유 저장소를 사용하는 제한과 세션 취소를 보완해야 합니다. 데모 입장은 실제 인증과 별개입니다. 인증 계정의 프로필·리뷰·시간표는 D1에 저장하며 서버에서 소유권을 검사합니다.

공식 배재대 포털에서 사용자의 실제 로그인 후 `/main.do`와 로그아웃 요소를 확인했습니다. 비로그인 요청은 로그인 화면으로 돌아갑니다. 앱 서버를 통한 실제 계정 로그인에서 성공 응답(200)과 이후 세션 확인 요청을 확인했고, 사용자가 앱 로그인 성공을 확인했습니다. 공개 구조와 테스트 도구는 docs/school-auth-investigation.md에 기록했습니다.

검증: `node --experimental-strip-types scripts/auth/test-auth.mjs`는 로컬 생성 RSA 키로 암호화, 합성 응답으로 성공/실패·외부 리다이렉트 차단·쿠키 격리, 세션 위조와 만료를 검사합니다. 실제 학교에 잘못된 계정을 보내는 테스트는 하지 않습니다.

## 데모 데이터와 검증 범위

데모 모드의 시간표·리뷰와 예시 활동 저장 목록은 메모리에만 있고 새로고침하면 초기화됩니다. 인증 계정의 시간표·리뷰·프로필은 유지됩니다. 실제 신청, 푸시 발송, 운영자 신고 처리는 연결하지 않았습니다.

프로덕션 빌드, TypeScript 검사, 작성한 app 및 공지 파서의 lint, 공지 파서의 링크 검증 테스트, 로컬 API 응답을 확인합니다. 기본 템플릿의 사용하지 않는 UI 컴포넌트에는 기존 lint 오류가 있어 해당 공급 코드는 수정하지 않았습니다. 학교 인증은 사용자 동의하에 별도 공식 포털 창에서 직접 로그인해 조사했습니다. 그 밖의 화면 전체에 대한 브라우저 조작 테스트는 실행하지 않았습니다. 선택적 WebMCP 도구는 지원 브라우저에서만 등록하며 현재 환경에서 실제 등록·실행은 검증하지 않았습니다.

## 회원 프로필과 학기별 시간표

학교 로그인 성공 후 학교와 HMAC 식별자로 기존 회원을 조회하거나 새 회원을 만듭니다. 첫 설정에서 직접 입력한 실명과 자유롭게 변경할 수 있는 닉네임·아바타를 저장합니다. 이름은 본인의 실명을 직접 입력하도록 안내하지만 학교에서 검증한 값은 아닙니다. 리뷰마다 이름/닉네임을 선택하며 서버는 선택된 표시명만 공개합니다.

첫 프로필 저장 후 학년도·1/2학기를 선택하여 수업을 수동 입력합니다. 나중에는 우측 상단 프로필 → 학기별 시간표 설정에서 변경합니다. 시간표는 회원·학년도·학기별로 저장하며 수업 추가/수정/삭제와 시간 중복 검사를 지원합니다. 현재 시간 범위는 월~금 09:00–18:00입니다. 대학 시간표 자동 수집은 구현하지 않습니다.

D1 바인딩은 `DB`이며 `db/schema.ts`와 `drizzle/`의 생성된 마이그레이션으로 관리합니다. 런타임에서 테이블을 만들지 않습니다. 로컬 DB에는 0000과 0001을 적용했습니다. 기존 게시 사이트에는 이 변경을 배포하지 않았습니다.

현재 회원 식별 HMAC도 SCHOOL_SESSION_SECRET을 사용하므로 데이터 유지 중 이 값을 교체하면 기존 회원 연결이 끊깁니다. 운영 전 식별 키와 세션 서명 키의 분리 및 키 이전 절차가 필요합니다.

`scripts/auth/test-member-api.mjs`는 로컬 합성 계정만 사용하여 인증/출처 차단, 프로필 유지, 학기 분리, 수업 중복과 소유권, 리뷰 표시명 공개 범위를 검증합니다. 실제 사용자의 시간표는 테스트로 추가하지 않습니다.

프로필 사진: JPG·PNG·WebP(최대 10MB)를 선택하면 브라우저에서 최대 512px JPEG로 변환하여 저장합니다. 사진 바이트는 R2 `PHOTOS`, 소유자와 객체 참조는 D1에 저장합니다. 사진이 없거나 삭제하면 선택한 기본 아바타를 사용합니다. 업로드는 즉시 저장되며 이름·닉네임·기본 아바타는 변경사항 저장 버튼으로 저장합니다. 사진 조회는 같은 학교 인증 세션이 필요합니다. 사진 업로드·삭제는 본인 계정에만 적용됩니다. 0002 마이그레이션을 로컬에 적용했고 사진 API 검증 및 빌드가 통과했습니다.

## 실제 행사 후보 가져오기

`/api/events`는 배재대 일반공지 1~3페이지와 교내행사 첫 페이지에서 최근 120일 이내의 행사/교육/프로그램 후보를 찾고 최대 16개 본문을 동시 2개씩 읽습니다. 선정·결과 공지와 제목상 이전 연도 행사는 제외합니다. 요청 시 수집하며 10분 메모리 캐시를 사용합니다. 수집한 행사는 D1에 출처·게시일·최초/최종 수집 시각·원본 해시와 함께 보관합니다. 별도 주기 작업은 아직 없으며 이 범위 밖의 공지는 수집하지 않습니다.

본문의 명시된 일정·신청기간·대상·장소를 근거로 표시합니다. 연도와 단일 행사 날짜, 시작·종료 시간이 모두 명확할 때만 선택한 학기 시간표와 이동 10분을 포함하여 비교합니다. 시간표 여유는 신청 자격/정원/접수 가능 판정이 아닙니다. 포스터 OCR·첨부파일 분석·여러 회차 및 생략된 날짜 추론은 하지 않으며 원문 확인으로 표시합니다. 기존 예시 활동과 별도 카드로 제공합니다.

실제 수집 검증: 행사 후보 9건, 본문 요청 실패 없음. 과거 교내행사 공지도 포함될 수 있어 지난 행사/이전 연도 표시를 구분합니다. `scripts/events/test-events.mjs`에서 신청일과 행사일 분리, 잘못된 날짜/생략된 연도/다일 일정 제외, 학기 일치 및 시간표 충돌을 검사합니다.

행사 카드는 제목과 학교 원본 포스터 중심으로 표시합니다. 공식 본문의 www.pcu.ac.kr/upload/ 이미지 URL을 중복 제거하여 최대 4개 연결하며 이미지를 누르면 공지 원문을 엽니다. 이미지가 없거나 로딩에 실패하면 원문 링크를 제공합니다. 기존 본문 일정 추출과 시간표 비교는 유지합니다.

## 실제 데이터 전환

홈에서 예시 활동·공간·리뷰·초기 수업 데이터와 데모 입장을 제거했습니다. 로그인 후 실제 학교 행사와 공지, 계정에 직접 입력한 시간표·프로필만 표시합니다. 예시 공간의 기존 리뷰 레코드는 삭제하지 않았지만 확인된 실제 공간 목록이 연결되기 전까지 리뷰 화면은 빈 안내 상태입니다. 데모 저장·알림 메뉴도 제거했습니다.

행사와 공지는 화면에서 1분마다 재확인하며 학교 원문 수집은 행사 10분/공지 5분 캐시를 사용합니다. 학교의 실시간 푸시 연동은 아닙니다. 공지 실패 시 예전 고정 스냅샷 대신 연결 오류를 표시합니다. 행사는 명확히 종료·마감되었거나 이전 연도로 판정한 후보를 목록에서 제외합니다.

시간표 비교 엔진은 여유/충돌/확인 필요/종료 상태와 근거를 반환합니다. 행사 전후 이동 여유 0·10·20·30분을 선택할 수 있고 여유 행사를 우선 정렬합니다. 겹치는 수업 이름·시간을 표시하며 진행 중 행사와 오래된 수집 자료는 여유로 판정하지 않습니다. 포스터 속 시간 OCR은 포함하지 않으므로 본문에 명시된 날짜·시간이 없는 행사는 확인 필요로 남습니다.

## 포스터 OCR (로컬 서버 연결)

Apple Vision을 사용하는 macOS OCR 브리지를 `scripts/ocr/`에 추가했습니다. `npm run ocr:build`로 실행 파일을 만들고 `npm run ocr:dev`와 앱 개발 서버를 함께 실행합니다. 앱 서버만 비밀 토큰으로 OCR 브리지에 접근하며 브리지는 127.0.0.1:4318에서만 수신합니다. `.dev.vars`의 POSTER_OCR_URL/POSTER_OCR_TOKEN은 Git에서 제외됩니다. 공개 학교 포스터 바이트만 전달하며 학교 계정·비밀번호·시간표는 OCR 서버로 보내지 않습니다.

이미지 크기 8MB/24MP, OCR 동시 실행 2건, 30초 처리 제한을 적용합니다. 이미지 내용 해시와 엔진 버전으로 D1 poster_ocr 결과를 재사용합니다. 새 이미지면 다시 분석합니다. 0003 마이그레이션을 로컬에 적용했습니다.

일시 라벨과 인접 행에서 단일 날짜/시간 또는 시작시간+명시적 소요시간을 읽습니다. 연도가 생략되면 공지 제목에 하나의 명확한 연도가 있을 때만 사용하고 화면에 근거를 표시합니다. 요일 불일치, 다회차, 신청기간, 낮은 인식 신뢰도는 자동 비교에 쓰지 않습니다. 신뢰도 0.5~0.9는 일정 후보를 보여주고 0.9 이상에서만 기존 시간표 엔진에 전달합니다. 신뢰도는 정확성 보장이 아닙니다.

실제 프레젠테이션 특강 포스터에서 2026-09-16 15:00–16:30 후보를 추출하고 API 응답에서 확인했습니다. 해당 OCR 줄 신뢰도는 0.5로 자동 추천하지 않습니다. 테스트에서는 날짜/요일/연도 근거, 명시된 소요시간, 모집일 분리와 복수 회차 거부를 검증했습니다.

현재 OCR 실행기는 이 Mac에서만 동작합니다. 모바일 앱 공개 서비스나 기존 Sites 배포에서 사용하려면 접근 가능한 인증된 OCR 서비스(동일 JSON 계약의 POSTER_OCR_URL)를 운영하거나 클라우드 OCR 어댑터를 연결해야 합니다. 이번 변경은 로컬 앱에만 적용했습니다.

## Mac 호스팅

`npm run build` 후 `npm run host:mac`으로 빌드된 Worker 앱과 OCR 브리지를 함께 백그라운드 실행합니다. `npm run host:mac:status`, `npm run host:mac:stop`으로 상태 확인/중지합니다. 데이터는 기존 `.wrangler/state`에 유지하며 실행 중 caffeinate가 자동 유휴 잠자기를 방지합니다. 덮개 닫기/전원 종료/재부팅은 서비스를 중단할 수 있습니다. 로그인 시 자동 시작은 설치하지 않았습니다.

외부 HTTPS 접속용 명령은 `npm run host:mac:public`입니다. Cloudflare Quick Tunnel은 테스트용 임시 주소이며 재시작 시 주소가 바뀔 수 있습니다. 사용자가 공개 범위를 확인하고 추가 승인하여 외부 HTTPS 연결을 실행했습니다. 일반 로컬 호스팅 명령은 터널을 시작하지 않습니다.

공개 접속 경로는 Cloudflare → loopback 게이트웨이(3010) → 앱(3000)입니다. 게이트웨이는 지정된 공개 호스트와 HTTPS, 변경 요청 Origin을 검사하고 앱의 명시된 API/정적 자산만 허용합니다. 쿠키에 Secure를 추가하며 OCR 포트와 디버그 경로는 공개하지 않습니다. 학교 로그인 요청은 Cloudflare를 경유합니다. 고정 주소 및 상시 운영은 도메인/Named Tunnel 구성과 별도 운영 검증이 필요합니다.

공개 접속 검증: 화면/정적 파일 200, 인증 없는 프로필 401, 디버그/환경 파일 404, 잘못된 Origin 403을 확인했습니다. 현재 임시 주소는 `.local-host/public-url`에 저장됩니다. 실제 학교 계정으로 휴대폰 로그인은 사용자가 직접 확인해야 합니다.

## Mac 서버 관리자 실행기

프로젝트 폴더의 `대대일모 서버 관리자.app`을 더블클릭하거나 `npm run admin:mac`을 실행합니다. 실행기는 별도 관리 서버(127.0.0.1:4320)를 켜고 브라우저에서 Mac 전용 관리 화면을 엽니다. 전체 네이티브 UI 앱이 아니라 Mac 실행기 + 로컬 웹 관리 화면입니다. 프로젝트를 옮기면 앱의 내장 경로를 다시 생성해야 합니다.

서버/OCR/외부 게이트웨이 포트 상태, 외부 접속 주소, 회원·수업·리뷰·OCR 개수, 회원 검색/이름·닉네임 수정, 회원별 수업·리뷰 조회/확인 후 삭제, DB 백업(사진 제외)을 제공합니다. 관리자 기능은 공개 프록시 허용 목록에 포함하지 않습니다. 관리 API는 매 설치마다 생성한 토큰, loopback Host, 쓰기 요청 Origin을 확인합니다. 관리자 토큰·로그·백업은 `.local-host`에 있고 Git에서 제외됩니다. 관리자 화면을 닫아도 관리 서버는 남아 있어 앱 서버를 다시 시작할 수 있습니다.

로그인 기록은 기능 적용 이후 성공한 로그인과 해당 브라우저 로그아웃부터 저장합니다. 학교 비밀번호/원문 학번/쿠키를 기록하지 않으며 회원 식별용 HMAC subject로 이름·닉네임과 연결합니다. 최근 30일/최대 200건을 표시하며 세션 만료 전이라는 정보는 온라인 접속 여부가 아닙니다. 기록 저장 실패는 로그인 자체를 차단하지 않고 오류만 기록합니다. 기존 로그인 이력을 소급 복원하지 않습니다. 0004 마이그레이션을 적용했습니다.

검증: 관리자 토큰/Origin 차단, 임시 회원 프로필 수정, 명시적 확인 및 소유자 범위에 따른 리뷰·수업 삭제, 공개 주소에서 관리자 경로 404, 실행 중 앱에서 가상 세션 로그아웃 이력 저장을 확인했습니다. 테스트용 레코드는 모두 정리했습니다.

## 행사 목록 검수·탐색

0005 마이그레이션은 `campus_events`, `member_event_saves`, `member_event_opens`를 추가합니다. 기존 로컬 DB는 적용 전에 백업해야 합니다. 행사 수집 결과는 출처 게시판, 원문 URL, 최초/최종 수집 시각과 함께 저장되며 원문에서 추출한 내용이 바뀌면 관리자의 이전 검수 상태와 수정값을 자동으로 해제합니다. Mac 관리 화면에서 원문을 열어 행사 날짜·시간·장소·대상·신청 정보를 확인·수정하고 후보를 숨길 수 있습니다. 자동 추출만 된 공지는 학생 화면에서 확인 필요로 안내합니다.

학생은 행사 제목·장소·대상을 검색하고 분야를 고르거나, 회원 계정에 행사를 저장할 수 있습니다. 저장한 행사는 최근 수집 목록에서 사라져도 다시 볼 수 있으며 오래된 수집 자료에는 시간표상 여유를 확정하지 않습니다. 학교 원문 열기는 회원별 이벤트 ID와 시각을 기록하되 실제 신청이나 참여로 집계하지 않습니다. 두 API와 행사 API는 배재대 인증 세션을 요구합니다. 행사 수집 범위와 추출 정확도는 실제 공지 표본 검수가 필요하며, 검색·저장 기능만으로 사용자 가설이 입증된 것은 아닙니다.

## 로그인 없는 앱 미리보기

`/preview`는 학교 계정이 없는 사람에게 대대일모의 화면과 핵심 흐름을 보여 주는 모바일 시연 경로입니다. 운영자가 원문을 대조한 **실제 배재대 공지**만 공개하고, 시간표 입력·리뷰 작성은 저장되지 않는 화면 시연으로 명확히 표시합니다. 공식 공지 링크는 원문으로 바로 열립니다. 공개 `/api/preview/events`는 허용된 공지 필드만 반환하며, 회원·시간표·리뷰 데이터나 실험 기록은 노출하지 않습니다. `/`의 정식 앱은 계속 학교 인증을 요구합니다. 기존 `/experiment` 주소는 `/preview`로 이동합니다.

## 보관 중인 초대 링크 실험 구현

초대·동의·행동 측정 기능은 이전 구현 기록으로 남아 있지만 공개 시연에서 사용하지 않습니다. 공개 프록시는 실험 API를 차단합니다. 학생 실험을 다시 결정할 때만 아래 운영 절차를 검토하세요.

Mac 로컬 DB를 백업하고 0006 마이그레이션과 별도 세션·운영자 비밀키를 준비하려면 서버를 중지한 상태에서 `npm run experiment:migrate`를 실행합니다. 현재 Mac 로컬 DB에는 적용되어 있습니다. `npm run build` 후 Mac 서버를 시작하고 `npm run experiment:refresh`로 배재대 공개 공지 후보를 갱신합니다. 이 갱신 경로는 Mac의 loopback에서만 사용할 수 있으며 공개 프록시에서는 차단됩니다. Mac 관리자 화면에서 학교 원문을 대조해 후보를 `verified`로 표시해야 합니다. **검수되지 않은 행사는 실험 화면에 나오지 않습니다.** 2026-10-12 현재 후보 11건을 새로 수집했고 4건을 원문 대조 후 검수했습니다. 모두 기간형·복수 회차이므로 시간상 맞는 단일 행사는 아직 없으며, 실험 모집 전 추가 공급 확인이 필요합니다. 검수 기록은 `docs/mvp-event-audit-2026-10-12.md`에 있습니다.

공개 HTTPS 주소가 준비되면 Mac에서 `npm run experiment:invite -- create U01`로 초대 링크를 발급합니다. `U00`은 화면 점검용 코드이며 실험 결과 요약에서 제외됩니다. 토큰 원문은 생성 직후 한 번만 표시되고 DB에는 SHA-256 해시만 저장합니다. 임시 주소가 바뀌거나 링크를 잃어버리면 같은 명령으로 재발급해야 합니다. `npm run experiment:invite -- revoke U01`은 접근을 중지하고, `npm run experiment:invite -- delete U01`은 해당 참여자의 기록을 삭제합니다. `npm run experiment:invite -- summary`는 코드별 동의·목록 조회·원문 이동 **시도**만 보여 줍니다. 실험 결과표에는 실제 원문 열림 여부와 실패 이유를 별도로 적어야 합니다. 행사 공급·모바일 접속·링크 이동이 검증되기 전에는 실제 참여자 링크를 발급하지 마세요.

검증 명령: `npm run experiment:test`, `npx tsc --noEmit`, `npm run build`. 상세 기준은 `docs/mvp-detailed-design.md`와 `docs/mvp-execution-plan.md`에 있습니다.
